1. 定位与名词表

一句话定位：FTS5 是 SQLite 内置的全文检索虚表模块，一套 LSM 风格的倒排索引工业实现：写进内存哈希、提交时 flush 成不可变段、后台分层合并，读做多段归并。事实ext/fts5/fts5_index.c:22-43 设计自述；影子表清单 fts5_main.c:3713-3722
术语含义出处
虚表用 xCreate/xBestIndex/xFilter/xUpdate 等回调对外表现成表的东西，解析/规划/事务由 SQLite 提供事实 fts5_main.c:3763-3790
影子表虚表背后真实的普通表：t_data/t_idx/t_content/t_docsize/t_config事实 fts5_main.c:3713-3722
term分词器切出的最小搜索单位，内部带 1 字节编号：'0'=主索引，'1'..=前缀索引事实 fts5_index.c:51,7017-7031
segment 段一次 flush 产出的不可变倒排数据块，16-bit segid，无 interior 页，就是一条叶子链事实 fts5_index.c:407-418
page 页段内读写单位，默认约 4KB，对应 t_data 一行 blob事实 fts5_config.c:19 pgsz=4050
doclist / poslist含某词的行号列表（delta 压缩）/ 位置表（列号+词序号，列号<<32|偏移）事实 fts5_index.c:144-151；fts5Int.h:364-365
split key / 界标t_idx 的 term 列：每页起始下界（公共前缀+1 字节压缩），首行空串事实 fts5_index.c:4516-4539

dlidx跨多页大 doclist 的页内跳表，自己也是一棵小 b-tree事实 fts5_index.c:205-232

3. 分层与依赖方向

事实 依赖方向 main → storage → index（写/事务）与 main → expr → index（查询）；index 不认识 expr/main。如 storage.c:1069 调 index.c:6812。
事实 fts5_config.c 是共享底座，Fts5Config 被四层引用（fts5Int.h:228-272）。横切：tokenize + unicode2（读写共用）、varint/buffer 基元；附加 aux（bm25/highlight/snippet）、vocab。
推断 切分意图：把最难变、性能最敏感的“格式与合并”与最善变的 SQL 语义隔开。

4.4 合并 merge / optimize

触发：每次 hash flush 后（index.c:5827-5829）。事实 automerge 按 nWorkUnit(64)×nWork×nLevel 预算增量合并（index.c:5043）；crisismerge 某层 ≥16 段强制下压（index.c:5064，默认 config.c:22）；用户 INSERT INTO t(t) VALUES('merge',N)/('optimize') → IndexMerge/IndexOptimize（index.c:5961/5925）。执行 fts5IndexMergeLevel（index.c:4812）：k 路归并 → 顺序写新段 → 删输入段 → 更新结构。level 0 最新最小，越大越老越大；最多 64 层（index.c:57）。

5. 核心机制逐条拆解

5.1 磁盘格式：t_data 的 6 类记录与 rowid 编码

事实 t_data(id,block)（index.c:6904-6912），记录清单 index.c:80-118；t_idx(segid,term,pgno) WITHOUT ROWID（index.c:6908-6911）。rowid 位域 segid(16)|dli(1)|height(5)|pgno(31)，AVERAGES=1、STRUCTURE=10、MAX_PGNO=0x7FFFFF00（index.c:269-304）。t_idx 的 pgno 存 flag+(page<<1)（写 index.c:4314，读 2734-2736）。段删除按 segid 整段清（index.c:1017-1040）。
页头 4B（首 rowid 偏移 + szLeaf），页脚 pgidx 为 term 偏移 delta-varint（index.c:171-204,621-625）。term 前缀压缩、每页首 term 全量、跨页首 rowid 绝对值（128-170,190-204,4483-4559）。无 free space，打包满即 flush；poslist 按 varint 边界切页（4498-4504,4599-4627）。

5.2 doclist / poslist / detail 三档

事实 doclist = 首 rowid 绝对值 + {delta,poslist}*（index.c:144-151）。位置值 (col<<32)|offset，跨列天然不相等（Int.h:364-365）。
full：collist + 0x01+列号增量，offset +2 编码，尺寸 varint = 字节数*2+bDel（buffer.c:236-251, index.c:1873-1881）；columns：列号当位置（hash.c:370）；none：只有 rowid delta + 0/1/2 个 0x00（index.c:1898-1911）。枚举 FULL=0/NONE=1/COLUMNS=2（Int.h:285-287，解析 config.c:404-416）。删除写 nPos==0 标记，merge 时 annihilation（index.c:4873-4874）。

5.3 内存 hash 与 flush

事实 Fts5Hash 1024 槽、装载因子 2 扩容（hash.c:28-35,281-285），key = 索引号字节+term，value 为内存 doclist。结束 32 路归并排序顺序写段（hash.c:447-488）。flush 触发：rowid 回退/同 rowid 二写/pending>1MiB（index.c:6812-6834，默认 config.c:23）。hash 同时当“伪段”参与查询归并，未提交立即可查（index.c:2873-2934）。推断 用 hash 而不用 b-tree：随机追加+周期整体输出，一次排序即顺序写段，避免页平衡写放大。

5.4 dlidx、t_idx、structure

事实 dlidx 只对跨 ≥4 续页的大 doclist 建（MIN_DLIDX_SIZE=4，index.c:49,4278-4289），自己是 b-tree（205-232），记录每页首 rowid，加速 seek 与大多合小多。t_idx 查询 SELECT pgno … WHERE segid=? AND term<=? ORDER BY term DESC LIMIT 1（index.c:2691）。structure 在 rowid=10：nLevel/nSegment/nWriteCounter + 每层 nMerge/nSeg + 每段 segid/pgnoFirst/pgnoLast（V2 加 origin/tombstone 统计），带一致性校验（1429-1479,1125-1228），缓存靠 PRAGMA data_version 判失效（1316-1334）。

5.5 前缀索引 prefix=

事实 上限 31 个、长度 1..999（config.c:271-291）。同一段内 key 首字节分区：'0' 主、'1'.. 第 i 个前缀（index.c:51,7017-7031）。长度按字符数换字节（6955-6976）。查询三路（7452-7503）：恰等长前缀索引直取；+1 长索引+主索引归并；否则主索引 16 路级联（MERGE_NLIST=16，6196）。调试开关 FTS5INDEX_QUERY_TEST_NOIDX 强制第三路（Int.h:439）。

5.6 tombstone（contentless_delete=1 才有）

事实 删除把 rowid 写进覆盖它的段的墓碑哈希页（IndexContentlessDelete index.c:8166，区间判定 8176-8182）。页格式 8B 头 + 槽位 iPg=rowid%nHashPg, iSlot=(rowid/nHashPg)%nSlot（234-266,7873+）。归并时跳过（3426-3431），按占比 ≥deletemerge（默认 10%，config.c:25）触发 delete merge 真清（4948-4980）。未知 查询侧函数名行号有两说未逐一复核，见 §10。

5.7 查询求值：MATCH 语法与 lazy 迭代器

事实 词法 expr.c:204-266（仅 OR/NOT/AND 保留字，bareword 表 buffer.c:313-330）；优先级 OR<AND<NOT<TERM<COLON（parse.y:76-80）；隐式 AND 只对 nearset 列表（132-135）；^ 打 bFirst 要求 offset==0（1648-1652,670）；* 只作用短语末 token（1889-1891,985）；空短语恒不匹配、深度上限 256（20-22,65-67）。节点唯一虚函数 xNext(…,iFrom) 允许跳到 ≥iFrom（expr.c:81）。TERM 快路径借用 poslist 指针（1229-1252）；短语多路 reader 对齐 iPos+i（605-687）；NEAR 滑窗 iMin=iMax-nTerm-nNear 就地裁剪（743-831,767-780）；AND 最大收敛、OR 选最早去重、NOT=child0 AND NOT child1（1332-1427）；detail≠full 短路只判存在（906-918）。推断 lazy pull 用 CPU 换内存与早期终止：O(1)/行内存、seek 下推、aux 按需物化。

5.8 分词器体系

事实 每连接注册、建表绑定，读写共用同一实例；统一入口 sqlite3Fts5Tokenize（config.c:801-826）。v1 注册 unicode61/ascii/trigram，v2 注册 porter（tokenize.c:1460-1495）；默认 unicode61（main.c:3286-3290,3459-3460）。unicode61：ASCII 快表+UTF-8 分类，类别 0 恒 token，折叠 1:1，去变音三档 SIMPLE 跳 HIBIT（tokenize.c:442-544, unicode2.c 全文件）。porter：v2 包装器，默认包 unicode61，>64B 透传，规则由 mkportersteps.tcl 生成内联（552-619,746-1167）。trigram：<3 字符无 token，abc*≡abc，LIKE/GLOB 改写超集+回查，提前实例化判 ePattern（1349-1454, expr.c:364-430）。v1/v2 双向自动适配（main.c:3303-3452）。回调必须按序、COLOCATED=0x0001 表同义词、DONE 视成功（fts5.h:477-498,643-650）。MAX_TOKEN 32768（Int.h:95）。分词串存 sqlite_master，是格式一部分（config.c:298-337）。

5.9 事务、影子表、rank 数据链

事实 模块 iVersion=4、fts5_api=3、ExtensionApi=4（main.c:3765,3802,2833）。%_content/%_docsize/%_config 由 StorageOpen 建（storage.c:343-417）。external 不建 content 直读外部表（100-142,365-393）；contentless 无 content，DELETE 需 contentless_delete=1（main.c:2013-2023），rowid 靠 docsize 分配（storage.c:959-983）。savepoint 先 flush（main.c:3166-3211）。special 命令 delete-all/rebuild/optimize/merge/integrity-check/flush/配置键（1767-1835）。bm25：k1=1.2 b=0.75 IDF 下限 1e-6 返回 -score（aux.c:669-752）；D 来自 docsize、avgdl 来自 averages，经 auxdata 缓存（main.c:2174-2188,2511-2561, aux.c:601-697）。ORDER BY rank 走内部 sorter 子查询（main.c:1084-1134）。

8. 扩展点与常见陷阱

扩展点（插件作者路线）

1. 取 api：SELECT fts5(?1) + bind_pointer("fts5_api_ptr")（示例 fts5_test_mi.c:76-80）
2. xCreateTokenizer(_v2) 注册（main.c:3394-3452，iVersion>2 报错）
3. xCreateFunction 注册 aux（main.c:3216-3250，先 overload）
4. xFindFunction 按名找 aux，首参 cursor id 找回游标再 invoke（3121-3141,2936-2959，api iVersion=4 实例 main.c:2832）
事实 全见 notes/fts5-config-aux.md §7。

常见陷阱

  • t_idx.term 是 BLOB，手写 SQL 必须 CAST('0…' AS BLOB)，TEXT 比较恒空（BLOB>TEXT）。
  • full-text 不加引号：- 被当列过滤，报 no such column（引号包起来）。
  • segid 会复用，不做业务标识；structure 非 per-term 摘要别记反。
  • tokenize 串存 sqlite_master，换分词器=换格式，旧库需重建。
  • contentless 默认禁 DELETE/UPDATE、无原文导致 snippet/highlight 为空。
  • detail≠full 禁短语/NEAR/^/列过滤；columnsize=0 伤 bm25 精度。
