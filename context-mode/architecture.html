01它是什么

一句话定位

事实 context-mode 是一个 MCP 服务器 + 多平台客户端插件，解决"AI 编码代理的上下文窗口被原始数据灌满"的问题：把大数据留在沙箱和本地 SQLite 知识库里，只把结论放进模型上下文；对话被压缩后，再从本地事件库按需取回工作记忆。package.json:5 · README.md:32-51

拆开看，它同时扮演四个角色：

① 沙箱执行器

11 种语言（JS/TS/Python/Shell/Ruby/Go/Rust/PHP/Perl/R/Elixir/C#）在子进程里跑代码，只回传 console.log 的结果。"让模型写代码分析，而不是读数据"。

② FTS5 知识库

SQLite FTS5 双索引（porter 词干 + trigram 子串）+ RRF 融合排序 + 邻近度重排 + 拼写纠正。索引过的内容用 ctx_search 按需取回。

③ 会话记忆库

hook 每次工具调用都抽取事件（文件改动、git、决策、错误、计划……约 30 类）写入 SQLite；压缩时生成"目录"快照，恢复时按需检索，不整包倒回上下文。

④ 路由拦截层

hook 在工具执行前拦截：curl/wget 被改写、WebFetch 被拒、大 Read 被标重定向、子代理 prompt 被追加路由指令——把模型"赶"向沙箱工具。

02如何运行

两条路：终端用户怎么装、开发者怎么起。

用户安装（Claude Code 为例）

/plugin marketplace add mksglu/context-mode
/plugin install context-mode@context-mode
# 重启 Claude Code；验证：/context-mode:ctx-doctor

事实 插件清单把 MCP 服务器注册为 node ${CLAUDE_PLUGIN_ROOT}/start.mjs，hooks 由静态 hooks/hooks.json 注册；其他平台（Gemini/Codex/Cursor…）走 npm install -g context-mode + 各配置目录，详见 docs/platform-support.md。.claude-plugin/plugin.json · hooks/hooks.json

MCP 服务启动后的运行链（每次宿主打开会话都会发生）：

  • start.mjs：修正项目目录 env →（Linux）用 Bun 重执行自身绕开 better-sqlite3 崩溃 → 插件缓存自愈 → 检查依赖（必要时后台 npm install）→ import server.bundle.mjs。
  • server.bundle.mjs：起 stdio JSON-RPC、注册 11 个工具、写就绪哨兵、开始统计心跳。
  • hook 进程：在每次工具调用前后被宿主独立 spawn。

开发者（在源码仓库里）

npm install
npm run dev          # = npx tsx src/server.ts  直跑 MCP 服务
npm run build        # tsc → build/，再 esbuild 出 6 个 bundle + 两个完整性断言
npm test             # vitest（pretest 会先 build）
npx tsx src/cli.ts doctor   # 或 npm run doctor

事实 Node ≥ 22.5；包里同时有 bun.lock 与 pnpm 声明；测试用 vitest，pool:"forks" 因为 better-sqlite3 在 worker 线程下会崩。package.json:81-126 · vitest.config.ts

04主流程时序

三条核心路径：一次工具调用的生命周期、工具的拦截路由、压缩恢复。

4.1 一次 ctx_execute：从调用到"字节留在沙箱"

  1. 宿主发起 MCP 调用
    handler 外面包了 in-flight 标记（防长任务被空闲回收）与错误兜底。
    server.ts:294-320
  2. 安全关卡（双保险）
    shell 代码先按用户 permissions.deny 拆链+拆子 shell 匹配；非 shell 代码正则提取 execSync(...)/subprocess.run(...) 等内嵌命令再匹配。任一段命中 → 拒绝。
    server.ts:1111-1162 · security.ts:174-314
  3. 插桩（仅 JS/TS）
    影子 require 拦截 fs.readFileSync 与 fetch/http，统计"留在沙箱的字节"，进程退出时以 __CM_FS__/__CM_NET__ 写 stderr，服务端剥离计数进 bytesSandboxed。
    server.ts:1761-1819
  4. PolyglotExecutor 执行
    临时目录写脚本（按语言补包装）→ runtime 探测出的命令行 → env 净化（约 90 个危险变量禁掉）→ Unix 上建独立进程组 → 超时杀全组、输出合计 100MB 硬顶。所有语言 cwd = 项目根。
    executor.ts:282-571 · runtime.ts:644-671
  5. 按体积走的返回策略
    见图 2：＞5KB+intent 走意图检索（目录式返回）；＞100KB 自动索引返回指针；否则原样返回（前置执行回显供审计）。
    server.ts:1912-1941
  6. 记账（trackResponse）
    累加每次调用的 calls / bytes → 500ms 节流写状态栏 sidecar JSON（含省下的 tokens 与折算金额）→ 异步写 SessionDB 计数并发射事件；沙箱类工具另发 bytes_avoided 事件。
    server.ts:885-966

4.3 压缩与恢复：快照是"目录"，不是"正文"

  1. PreCompact
    读全部会话事件 → 生成 XML 快照（目标、文件 top10、错误、决策、规则、git、任务、环境、子代理、技能、角色、意图、最近 3 条用户消息；每节内嵌一条可直接运行的 ctx_search 调用）→ 写入 session_resume（consumed=0）。

    新 session id 没有 live 事件时，用 UPDATE … RETURNING 原子领取上一条未消费快照注入（防重复领取/自我注入）。

05核心机制拆解

八条机制，每条都可独立当"改这块代码前的必读"。

5.1 沙箱执行：三件套（进程隔离 + env 净化 + 输出护栏）

  • 进程：Unix 上 detached:true 建进程组，超时用负 PID 杀整组；Windows 用 taskkill /F /T；background:true 时超时不杀、unref 后把管道换成 no-op 排空（避免 SIGPIPE 杀掉子进程）。executor.ts:196-208, 475-508
  • env：约 90 项 denylist（BASH_ENV/NODE_OPTIONS/LD_PRELOAD/DYLD_INSERT_LIBRARIES/DOTNET_*/CORECLR_PROFILER*/GIT_SSH*…），外加 BASH_FUNC_*、COMPlus_* 前缀清扫；强制 TMPDIR 指向沙箱、NO_COLOR=1。executor.ts:573-745
  • 护栏：stdout+stderr 合计 100MB 硬顶（超了直接杀并注明）；默认不设超时（issue #406：超时归宿主 RPC 管）；Rust 先编译再跑、编译限 60s。executor.ts:510-547, 377-407
  • 怪招备忘录：OS_TMPDIR 绕过被 shell 改写的 TMPDIR；Windows Git Bash 裸 mvn → mvn.cmd；PowerShell 5.1 脚本加 UTF-8 BOM；Go/PHP 自动补包装。

5.2 安全策略引擎：复用宿主自己的权限配置

  • 读的是用户已有的 .claude/settings[.local].json 与各 adapter 全局 settings 的 permissions.{allow,deny,ask}——不自造一套配置。security.ts:363-490
  • 防绕过：按 && || ; | & 拆链、递归提取 $() 与反引号子 shell，任意一段命中即拒；echo ok && sudo rm -rf / 拦得住。security.ts:174-314
  • 文件路径同一路径三形态匹配（原样 / 词法绝对 / realpath），防 .. 穿越与符号链接逃逸；项目边界围栏把 ctx_execute_file 钉在项目根内，逃生门是用户已有的 permissions.allow: ["Read(...)"] 规则。security.ts:616-783 · server.ts:1184-1209
  • 服务器侧只有 deny 模式（没有 UI 问用户）；任何检测异常一律放行——注释明说"hooks 才是主执法层"。server.ts:1127-1131

5.3 检索管线：两个匹配器 + 一层融合 + 三层修补

  1. 查询清洗：剥 FTS5 元字符、去操作词与停用词、逐词加引号——语法注入防御。store.ts:90-125
  2. RRF 融合：porter 词干表与 trigram 子串表并行检索，Σ 1/(60+rank+1) 融合——两边都好的文档排最前。
  3. 邻近度重排：top 结果按"查询词靠得近"加分（标题命中权重最高）。
  4. 模糊纠正：零结果时用 vocabulary 表 + Levenshtein 改词重搜（容差按词长 1/2/3）。
  5. 搜索用 40KB 输出上限 + 防刷闸：60 秒窗口内第 4 次查询起每查询只给 1 条，第 8 次直接拒绝并命令改用 ctx_batch_execute（按 agent 会话键控，子代理不互相挤占）。server.ts:2457-2470, 2655-2679

5.4 分块策略：按内容形态四套打法

  • Markdown：H1–H4 标题栈组块（path > to > title），代码围栏整块保留；4096B 上限按空行拆。
  • 纯文本：最优先按空行分段（3–200 段且每段 <5KB），否则固定 20 行 + 2 行重叠。
  • JSON：递归遍历，标题=键路径；数组按 identity 字段（id/name/title…）分批命名。
  • 目录：有界遍历（深度 5、文件 200、扩展名白名单、尊重 .gitignore、默认不跟符号链接）。store.ts:1646-2022 · store-directory.ts

5.5 输出回显与审计（#717/#736 的教训）

execute 类工具返回的文本以一个"回显"开头（执行的代码 / 处理的路径，代码最长 2000 字符、命令 500 字符，超长截断标注），让用户和宿主 tooling 能审到实际执行了什么。server.ts:1477-1527 · buildExecuteEcho:1523

5.6 会话事件系统：约 30 类事件 + 去重 + 淘汰

  • PostToolUse 抽取：文件读写改、git/commit、错误及"错误解决"、任务、计划模式进出与批准/拒绝、技能、子代理、外部引用、worktree、bash 结果、重试检测等（约 30 类）。session/extract.ts:2710-2750
  • 写入策略：单事务"去重（5 条窗口）→ FIFO 淘汰（上上限 1000）→ 插入"，配 withRetry 抗 SQLITE_BUSY。session/db.ts:1173-1204
  • 归属：每事件算 project_dir + 来源 + 置信度（carry-forward），保证多项目共用存储时不错归。session/project-attribution.ts

5.7 兼容性防御（踩坑史最密集处）

  • OpenCode/Kilo 双注册抑制（#623/#637）：插件与旧 MCP 块并存时，MCP 子进程不再注册工具，并给出 stderr 诊断 + 显式空 tools/list（否则 SDK 回 -32601 误导用户）。
  • Gemini 严格函数调用：发出去的 schema 做 const→enum、删 additionalProperties（#854 注释）。server.ts:353-413
  • 空 prompts/resources handler 防传输层毒化（#168）。
  • 版本检查：响应里自动插入 outdated 提醒（最多 3 次爆发、之后静默 1h）。server.ts:777-841

5.8 生命周期与自愈

  • MCP 侧：lifecycle.ts 看护父进程存活（防孤儿），bridge 子进程另有空闲自灭（#854）。
  • 启动侧：start.mjs 六层自救（Bun re-exec / 缓存 heal / env heal / hook normalize / 依赖 ensure / 部分安装补全 + 完整度闸 exit 2）。
  • 数据侧：陈旧 DB 清理（死 PID、14 天）、WAL 僵尸库检测、损坏库重命名/重建、退出时 checkpoint。多写者契约见 ADR-0001。

08扩展点与常见陷阱

想加一个新平台适配器

  1. 在 src/adapters/<name>/index.ts 实现 HookAdapter（从 types.ts:172-322 抄契约；JSON-stdio 平台多半能继承 ClaudeCodeBaseAdapter）。
  2. 在 detect.ts 的 PLATFORM_ENV_VARS 注册识别 env，并在 getAdapter() 的 switch 挂上。
  3. 在 hooks/core/ 加该平台的事件格式化（formatters.mjs 的模式是纯函数 + 平台分支）；HOOK_MAP（cli.ts:77-156）与 configs/<name>/ 补配置。
  4. 版本同步：若平台有 plugin.json，把路径加进 version-sync.mjs 的 TARGETS。

想加一个新工具

  1. 在 server.ts 用 server.registerTool() 注册（描述必须按 ADR-0002 的 WHEN/WHEN NOT/RETURNS/EXAMPLE 格式）。
  2. handler 内先跑安全关卡（shell → checkDenyPolicy；文件 → checkFilePathDenyPolicy/checkProjectBoundary）。
  3. 返回一律包 trackResponse()（否则统计断档）；布尔参数用 coerceBoolean 而不是 z.coerce.boolean()。
  4. 注册必须在模块顶层、且在 installStrictClientSchemaCompat() 调用之前（顺序在文件末尾收口）。

常见陷阱（读代码时容易踩的）

  • 别在 sandbox 里期待写文件生效：ctx_execute 的沙箱文件系统会被丢弃，持久写必须走宿主 Write/Edit（routing block 里也写明了）。
  • NODE_OPTIONS 被 env 净化禁掉：批量执行的 FS 统计靠命令串前缀注入，不是环境变量。
  • hook 永远 exit 0：排查"为什么没拦住"要去 hook-errors.log，而不是看退出码。
  • 重定向只在 MCP 就绪时发生：哨兵是 90s 新鲜度窗口，调试时留意 /tmp 哨兵是否还在刷新。
  • ctx_search 有防刷闸：自动化脚本里连搜会被 60s 窗口限制，批量问题请用一次 ctx_batch_execute。
  • SessionDB 没有 FTS5：事件检索是 LIKE；全文检索发生在 ContentStore（events.md 被索引后）。
  • 改 server.ts 要跑全部断言：bundle 与 schema 兼容层都在文件尾部顺序敏感。
