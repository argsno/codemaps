一、这是什么 事实

一句话：baoyu-design 是 Claude Design 的可移植重打包——技能本体是 Markdown 提示词 + 无构建 JSX 脚手架 + Node/TS 本地工具链，让 Cursor / Claude Code / Codex 等本地 Agent 在编辑器内完成"提问 → 设计 → 预览 → 导出"全流程，产物是自我包含的 HTML。

它是

  • 一套设计方法论 + 工艺标准（system-prompt.md，323 行）
  • 一套按需加载的专项技能库（built-in-skills/ ~50 个提示词）
  • 一套无构建脚手架（starter-components/ 27 个组件）
  • 一套本地工具链（agents/：导入 / 编译 / 预览 / 导出）

它不是

  • 不是运行时框架或 npm 应用（仓库 private: true，无发包）
  • 不是网站/服务（没有服务器代码，一切在本地文件系统）
  • 不是 Anthropic 官方项目（独立社区维护，README 明言无隶属关系）
  • 不是通用 HTML→PPTX 转换器（只导出本技能构建的 deck）

二、如何运行

三种视角：把它装进你的 Agent（用户视角）、跑起预览（日常）、开发/验证这个仓库（贡献者视角）。

2.1 用户视角：安装与使用 事实

# 推荐：Vercel Labs 的 skills CLI（自动探测你的 agent）
npx skills add JimLiu/baoyu-design          # 安装到当前项目
npx skills add JimLiu/baoyu-design -g       # 安装到用户级（所有项目可用）
npx skills update baoyu-design              # 更新

# 或者零安装：把 repo URL 丢给 agent，让它自己 fetch 并读 SKILL.md

之后直接用自然语言描述需求（"给冥想 App 设计 3 个设置的 hi-fi 变体"）；Claude Code 里也可用 /baoyu-design 显式触发。Agent 会自动：读方法论 → 识别 harness → 载入对应 built-in skill → 提问确认 → 在 designs/<project>/ 下产出 HTML → 起 HTTP 预览让你查看。

2.2 预览（交付物必须走 HTTP） 事实

python3 -m http.server 4311 --directory designs
# 打开 http://localhost:4311/<项目>/<文件>.html

为什么必须 HTTP：多文件原型用 <script type="text/babel" src="…jsx"> 加载组件，浏览器在 file:// 下会因跨源限制静默失败；统一用 4311 一个 server 服务整个 designs/。

出处：system-prompt.md:146,185。

2.3 仓库自身（开发/验证） 事实

npm test        # node --test skills/baoyu-design/agents/tests/*.test.mjs（零依赖）

# 导出工具的一次性构建（用不到可跳过）
cd skills/baoyu-design/agents/gen-pptx && npm install && npx playwright install chromium && npm run build
cd skills/baoyu-design/agents/gen-video && npm install && npx playwright install chromium && npm run build
# gen-video 另需 ffmpeg 在 PATH（macOS: brew install ffmpeg）

三、分层与依赖方向 事实

六层单向依赖：上层只以相对路径引用下层；工具链永远不会被内联进交付物，只在 Agent 构建过程中被调用。

四、主流程时序（入门 → 精通主干）

一次典型的设计任务从进入到出结果的完整链路。这是理解整个项目的骨架——每一格都标了对应源码位置，方便你直接跳进文件。

触发与读入口 Agent 因 description 自动激活技能（或用户显式 /baoyu-design），读 SKILL.md：先载方法论，再识别 harness。SKILL.md:23-40
识别 harness、载工具映射 看自己有哪些工具（如 AskUserQuestion+SendUserFile → Claude Code），读 references/<harness>.md 定下"问用户/预览/截图/验证"的具体调用法。system-prompt.md:10-14；references/*.md
路由：载入 built-in skill 按 project-types.json 13 类路由或关键词载入 built-in-skills/*.md；默认（普通设计）载 hi-fi-design+interactive-prototype。SKILL.md:42-60；project-types.json
这层是"需要才加载"的渐进式披露，避免把 50 个提示词一次性塞进上下文。
提一轮结构化问题（必做） 确认：设计上下文（UI kit / 设计系统 / 代码库 / 截图）、变体维度与数量、保存位置（默认 designs/<slug>/）、要用哪个设计系统（多选）。system-prompt.md:154-179；use-design-system.md 步骤 2
硬规则：每个新项目都当 fresh start——即便和上次请求一样，也不允许拿记忆里的方向当默认值。
发现并绑定设计系统（如选择） glob designs/*/_ds_manifest.json 发现可用系统 → 对每个选中的跑 node agents/import-design-system.mjs <dsDir> <projectDir> [--primary]： 同步 @import 闭包 CSS + url() 资产 + bundle 到 _ds/<slug>/， 生成 _ds_prompt.md，合并写 _d_meta.json。import-design-system.mjs:100-200
绑定是"版本化快照"：项目自包含；刷新 = 重跑 import（幂等）。
把 _ds_prompt.md 当作 binding 视觉契约 读 _ds/<slug>/_ds_prompt.md：接线代码（React UMD + 全部 <link> + bundle <script>）、组件用法摘录、props 契约、token 白名单。只能用白名单里的 var(--*)，不得自创颜色/组件。ds-prompt.mjs:154-286；use-design-system.md 步骤 5

HTTP 预览 + 验证 + 交付 起 4311 服务 → harness 浏览器工具截图/查控制台（若模型不支持图像输入，先跑 vision probe 并降级为文本/DOM 校验）→ 修错重验 → 把"运行中的预览"作为交付的一部分呈现给用户（URL + 文件）。system-prompt.md:181-187；references/claude.md "Vision input probe"

五、核心机制逐条拆解

八条机制构成这个项目的"设计逻辑"。读懂它们，你就理解了为什么文件被安排成这样。

5.1 可移植性 = 同一套 craft × 各 harness 的薄适配 事实

  • 方法论只写"能力名"（问用户、预览、截图、验证），不写具体工具；工具查 references/<harness>.md。system-prompt.md:6-16
  • 识别规则是"你有哪种工具→你是什么 harness"（见名词表）；不认识的环境走通用兜底流程。
  • 推断 新增一个 harness 的成本 = 一张工具映射表 + 识别行加一条，方法论零改动。

5.2 按需加载（渐进式披露）的路由 事实

  • 三份路由并存：project-types.json（机器可读 13 类）/ system-prompt.md 表格（人读）/ SKILL.md 分支（编排）。
  • 三方一致性由测试守护（project-types.test.mjs 断言三处都提到全部 13 类，且对应文件含指定 marker 串）。

5.3 设计系统：「绑定即契约」的版本化快照 事实

  • 根标记区分：DS 根有 _ds_manifest.json；项目根有 _d_meta.json。所以 glob designs/*/_ds_manifest.json 只会命中"被创作的系统"，不会命中项目里的消费副本（副本的 manifest 深一层）。
  • 拷贝集确定性：导入器复用只读解析器 ds-core.mjs 算出的 @import 后序闭包 + 这些 CSS 的本地 url() 目标，外加 bundle/manifest/adherence/README/SKILL 与 assets/。绝不碰源树。
  • binding 的载体是生成的 _ds_prompt.md：固定版本 React 标签、全部接线行、组件 props 契约（枚举值完整）、token 白名单、"text/babel 顶层禁用 window 全局名"清单（status/name/open/…，因为 Babel 注入成 classic script 会把顶层 const 变成 window 属性）。

5.4 资产记录与项目恢复（_d_meta.json） 事实

  • 模型：assets[显示名].versions[] = {path, createdAt, status, subtitle?, viewport?, section?}；status ∈ needs-review（默认）/ approved / changes-requested。
  • 同 path 再记录 = 原地更新（保留 createdAt）；新 path = 追加新版本；--inherit-from 把新文件归到已有资产名下。
  • 读取 _d_meta.json 是重开项目的入口：有 designSystems 就恢复绑定、不再重问。
  • 推断 这套"版本 + 审阅状态"的模型对应宿主产品的资产审查面板；本地用 CLI 复刻，保证无宿主时流程完整。

5.5 HTTP 预览纪律与验证闭环 事实

  • 一切预览/截图/打开 → http://localhost:4311/…；单 server 服务整个 designs/ 并复用。
  • 交付 = "运行中的预览"：给 URL + 文件；修到"不炸"为止。references/<harness>.md 里有各环境的预览怪癖（React 18 onClick 委托对合成点击不响应、reload 后截图错位等）。
  • 图像输入门控：Claude Code 场景先对 committed 的 vision-probe.png 跑一次性探测，只有子代理回精确 VISION_OK 才允许把截图读进模型；否则退文本/DOM 校验并明示"视觉审查被跳过"。

5.6 直接可编辑性（作者面向产物的约束） 事实

  • 产物需"canonical HTML"：显式闭合、双引号属性、不自动闭合。
  • 文本放叶子元素；重复结构写死，不用数组生成——为了让宿主的直接编辑（点选改字）能把修改 splice 回源码。
  • make-a-deck 特别强调：静态 HTML 优先，React/脚本生成的 DOM 会破坏这条路径。

5.7 固定尺寸内容与 deck-stage 事实

  • deck / 视频 / 打印文档等固定尺寸内容自实现缩放：1920×1080 画布 + letterbox + 控件在缩放元素外。
  • deck-stage 组件还提供：缩略图 rail（可拖宽、多选、重排、Skip、Delete）、打印每页一张纸、noscale（供导出器抓 1:1 几何）、dc-op 协议（结构性变更交给宿主，未确认前锁输入）。
  • data-anim 是 deck 与 PPTX 导出器之间的共享契约：组件负责浏览器内播放（WAAPI），gen-pptx 负责翻译成原生动画。

5.8 上游同步机制 事实

  • 上游 = claude.ai/design 的反混淆 bundle；references/upstream-sync/ 记录 sha256 溯源、提取 profile、原始 JSON 快照。
  • 同步动作有两类：copy（直接覆盖）与 preserve-for-merge（本地有改动的文件跳过覆盖，稍后手工合并）。受保护清单：9 个 skill + 2 个 starter。
  • 测试套件含"防回归 marker 断言"：如 deck-stage 必须含 _animOnNav、tweaks-panel 必须含 TweakSuggestionBar、design-canvas 必须含 1.1× 缩放实现——一次粗暴的上游同步会被 CI 直接拦下。

七、本地工具链深潜

四个最值得理解的实现：它们回答"云端工具怎么移植到本地"这个核心命题。

7.1 gen-pptx：不解析 HTML，而是"真浏览器渲染 → PowerPoint 翻译" 事实

  • 单位换算：px ÷ 96 = inch，px × 0.75 = pt；文本宽度额外补 3%（最少 8px）、高度 +4px 防换行漂移。
  • 动画：data-anim → 每个形状绑 spid（依赖 vendored 库的 cNvPr/@id = idx+2 契约）→ 生成 <p:timing> XML 写进 slide XML；复合滤镜效果只在主形状播、其余退化为 fade（避免 PowerPoint 按形状各自播种子打架）。
  • 为什么 vendor 源码：PptxGenJS 没有动画 API；patch 只有两处——把算好的 timing 字符串拼进 slide XML + 声明 _timingXml 字段。升级流程=换源码→重放 patch→跑测试（测试真跑 pptx.write() 解包断言契约）。

7.2 gen-video：桥 seek 逐帧 → ffmpeg 事实 注意·版本错位

  • 管线：等桥（8s 内每 50ms 轮询）→ 暂停播放 → 帧循环（bridge.setTime(秒) + 双 rAF 沉降 → 整视口 PNG）→ 帧流写入 ffmpeg -f image2pipe（mp4=libx264 / webm=vp9 / gif=palettegen+paletteuse）。
  • 超采样：DPR=2 截图，降采样交给 ffmpeg lanczos；帧时刻 (startMs + i*1000/fps)/1000。
  • 验证 4 flag 全为 advisory：zero_duration / fonts_timeout / capture_mode_off / duplicate_frames（阈值放宽到 85%，因为"讲解型动画每拍停几秒"是正常的）。
  • ⚠ 已知错位：CLI 只认 window.__animStage.setTime（默认桥名），而 __animStage 只在 v1 animations.jsx 存在；当前主力引擎 v3 的导出契约是 DOM 事件 data-om-seek-to-time-frame，CLI 不派发该事件。文档（export-as-video.md）又按 v1 零配置描述。→ 用 v3 新做的动画本地导出为视频目前没有文档化路径。

7.3 设计系统流水线（四脚本 + 一指南） 事实

  • ds-core.mjs（只读解析器）：算 @import 后序闭包、抽 --* token（带幻影匹配防护）、正则级解析 .d.ts props（fail-open）、收集 issues。零写入是刻意的——checker 可作为只读子代理运行。
  • compile-design-system.mjs（唯一写步骤）：Node 内跑 vendored Babel（preset react，自定义插件删 export/重写相对导入）；按依赖图 DFS 后序打 bundle；单文件转译失败降级为 __errors 条目而非整体失败。
  • check-design-system.mjs：输出 summary + issues；测试证明"写零"；无 CSS 入口 exit 2。
  • import-design-system.mjs：见 §5.3；生成 _ds_prompt.md 是它的隐藏主角。
  • build-preview.mjs：把 DS 编成单文件 preview.html——构建期做"CSS 作用域化（:root→:host、@font-face 提升）/ JS 转译 / 资源内联（含 JSX 字符串引用与运行时 fetch 代理）/ djb2 CSS 去重"；运行期用声明式 Shadow DOM + 每卡 document/window Proxy 沙箱 + 自适应缩放安全渲染。

7.4 Figma 离线解码 事实

  • .fig = ZIP（内取 canvas.fig）或裸 kiwi 容器；canvas 头 fig-kiwi + chunk 序列；chunk[0]=schema、chunk[1]=data。
  • 压缩：zstd（内联 base64 WASM 解码）或 deflate；schema 用 new Function 现场编译成解码器再解 data——这是"完全离线"的关键，不需要 Figma 的任何服务。
  • 子命令：outline（盘点）→ mount（参考树）→ materialize（发射组件 JSX）/ render（视觉基准 HTML）→ design-system（原料→走 §7.3 策展流水线）。
  • 资产：位图落 assets/（4MiB/张、16MiB 总预算）；小矢量内联 SVG、大矢量独立 .svg；字体权重按样式名解码成 100–900，但 .fig 不含字体二进制（提示自备 @font-face）。

八、工程化与测试 事实

  • 零依赖测试：node --test 跑 agents/tests/*.test.mjs（Node 22 内建 runner）；CI 在 Ubuntu + Node 22 上只做这一件事。
  • 三类测试：
    1. 纯函数/CLI 契约测试（asset-store、record-asset、ds-core 等）；
    2. 真实子进程冒烟（compile→manifest→bundle 可 new Function 执行；import-figma 真解 minimal.fig）；
    3. 文档一致性守卫（project-types.test：13 类路由三处对齐 + 上游同步防回归 marker；vision-probe-docs.test：把"AI 能力门控"写进断言）。
  • 两个导出 CLI 各有独立测试（gen-pptx：vendored 库契约真跑 pptx.write() 解包 + timing XML 结构化断言；gen-video：ffmpeg 参数 + validate 边界），但不在根 CI 里——需目录内单独跑（避免 Chromium 依赖进 CI）。
  • 发布：.claude/skills/release-skills/（本仓库自用）：自动探测版本文件/多语言 changelog → conventional commits 分析 → 多语言条目 + 版本 bump + annotated tag + GitHub Release；历史 tags v1.0.0–v1.3.0。

推断 测试重心与项目本质一致：能测的测死（工具逻辑、文档一致性、上游同步护栏），测不了的（浏览器内渲染、提示词质量）靠人工验证 + 明确记录盲区。

九、扩展点与常见陷阱

9.1 如果你想扩展它 推断（基于结构）

目标操作别忘了
支持新 harness写 references/<new>.md（工具映射 + 预览怪癖）+ 在 SKILL.md/system-prompt.md 识别行加一条方法论不用改；映射至少覆盖"问用户/呈现/截图/验证"四能力
新增 built-in skill加 built-in-skills/<name>.md（frontmatter name+description）同时在 system-prompt.md 清单 + SKILL.md 路由挂上；若属 13 类之一要动 project-types.json（测试会查）
新增 starter加 starter-components/<file>，头部写 usage 注释project-types.json 的对应类型 starters[]；若被 PPTX/视频导出依赖，注意与导出器的契约（如 noscale、时间线桥）
新增导出格式仿 gen-pptx 结构：CLI 壳 + orchestrator + 纯函数 core + 测试stdout 单行 JSON + 退出码 0/64/1 的约定；flags 命名与文档同步；导入式而非全局依赖（Playwright 动态 import 以便友好预检）
上游同步重跑提取/同步（工具不在本仓库）受保护清单；同步后跑测试套件（marker 断言会抓回归）；必要时重放 deck-stage/design-canvas patch

9.2 常见陷阱（均已见证据）

用 file:// 预览

多文件 Babel 原型会静默失败（跨源脚本读取被拦）。永远 HTTP + 4311。事实

Babel 顶层全局名撞车

text/babel 块被注入为 classic script，const status = … 会写 window.status 并静默炸掉页面。禁用清单（status/name/open/location…）写进了 _ds_prompt.md。事实

全局 style 对象重名

多个 Babel 文件各自作用域，const styles = {} 会互相覆盖；必须带组件名前缀或用 CSS 变量。事实

deck 幻灯片 wrapper 坍缩

deck-stage 只拉伸 section，不拉伸内部 wrapper；全绝对定位的 wrapper 高度为 0 → 全出血图消失/半屏。加 section[data-label] > * 的 height:100% 基础规则。事实

token 名靠猜

未解析的 var(--x) 静默回退浏览器默认值——所以 _ds_prompt.md 内置精确白名单，只许用列表内的名字。事实

v3 动画导出视频

见 §7.2 警示：本地 gen-video 与当前引擎的桥协议错位，导出前先确认桥或改用 v1 兼容引擎。注意

把 repo 当"代码"阅读

本仓库的"源代码"一半是提示词（影响的是模型行为而非运行时）。改提示词要同时考虑三处路由与测试 marker。推断

assets/ 与 vendor/ 的区别

根 assets/ 只服务 README；运行时离线依赖在 agents/vendor/（React/Babel/fflate/fig-materialize）。别搞混。事实
